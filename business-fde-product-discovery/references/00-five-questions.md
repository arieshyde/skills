# 五问：客户倒推的起点

五问用于澄清客户、问题、收益、证据和目标体验。它不是填空作业；答不出时，正确产物是证据缺口和验证计划，而不是更漂亮的答案。

## 零材料或材料不足时

先向用户展示已找到的材料和缺口，不直接代答五问。至少引导补充：项目为何启动、目标客户/用户是谁、已观察到的具体问题、可访问的访谈/会议/数据、当前做法，以及已知约束。用户暂时无法提供时，产出待访谈问题和资料收集清单，不虚构场景或答案。

若本轮输入与项目主题、既有客户、阶段或术语明显不一致，先指出不一致之处并询问是否切换项目或修订定义；在确认前暂停依赖该输入的正式写作。

## 一、五问

1. 客户是谁？分别写清主客户、实际用户、付款人和受影响者。
2. 客户的问题或机会是什么？用客户当前处境描述，不提前塞入解决方案。
3. 对客户最重要的收益是什么？只选一个主收益；其他收益降为次级。
4. 我们怎么知道？列出直接客户证据、行为数据及必要的外部背景，并按证据规范标状态。
5. 目标客户体验是什么？描述客户从发现、购买/采纳、启用、使用到获得支持的完整体验，不写功能清单。

## 二、强答案标准

1. **一致**：客户、问题、收益、证据和体验互相支撑。
2. **具体**：明确角色、场景、频率、影响和边界；数字只有在口径完整时使用。
3. **客户视角**：先写客户发生什么改变，再写产品做什么。
4. **智识诚实**：把未知、估算和假设标出来；不得用行业常识替代客户证据。
5. **可证伪**：关键结论能设计验证，不使用永远无法判错的表述。

## 三、证据门槛

- 第 1、2、4 问的客户事实判断需要直接客户证据；没有时在评审稿中标为待验证，并明确会议需讨论的补证或验证安排，不声称产品价值已证实。
- 行业报告可说明问题可能存在，不能证明目标客户一定需要或愿意采用。
- 单个客户原话不能自动推断整个市场；需要标注适用范围。
- 会议记录相互冲突时并列呈现，不替有权人裁决。

## 四、映射

- 问题进入 PR 的问题段和 PRD 的背景/痛点。
- 首要收益进入 PR 标题、摘要和产品定义台账。
- 目标体验进入 PR 的方案/使用体验和 PRD 的用户旅程。
- 客户角色决定客户 FAQ 的措辞和假想引语角色。
- 证据、冲突和假设进入台账与 FAQ；不要为了行文顺滑塞入 PR 正文。

## 五、输出与判断

1. 已有可靠五问时先校验，不机械重做。
2. 证据不足时在上会评审材料中列明未知、对决策的影响和获取证据的方式；负责人、期限无依据时写“拟请会议确定”。
3. 五问一致且关键主张有证据或明确假设后，才进入 PR/FAQ。
4. 后续文档暴露的新认知必须回写五问或产品定义台账。

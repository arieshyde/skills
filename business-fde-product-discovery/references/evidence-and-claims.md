# 证据与主张规范

## 一、主张状态

每个会影响范围、承诺、投资或验收的主张必须使用以下一种状态：

1. **已验证事实**：有直接证据，来源可访问且能定位。
2. **有据估算**：由已知数据计算或外推；必须给口径、区间和关键假设。
3. **待验证假设**：产品成立必须为真的命题，尚未获得足够证据。
4. **已批准决策**：有权人作出的范围或取舍，不等同于客观事实。
5. **未来目标**：团队希望实现的客户体验或指标，不得写成已经发生。
6. **未知待补**：目前没有可辩护答案；附获取方式、对本次决策的影响、负责人和最迟时点。负责人或时点尚无依据时写“拟请会议确定”，不得虚构或把建议写成已接受的安排。

禁止使用“行业普遍认为”“客户通常需要”“技术上应该可以”等措辞绕开状态标注。

## 二、来源层级

按主张类型选来源，不要求所有信息都来自客户会议：

1. 客户痛点、现状、使用行为、购买意愿：客户原话、现场观察、实际使用数据、客户确认记录。
2. 法规、标准、合同义务：正式发布文件、合同或经确认的合规意见。
3. 市场容量、竞品与行业背景：可追溯外部资料；记录机构、标题、日期、链接或文件位置及统计口径。
4. 技术可行性与能力边界：PoC、测试报告、平台文档、研发确认记录。
5. 成本、资源和经济性：内部工时、报价、采购、运维或财务数据；无法精确时给区间和敏感性。
6. 范围、优先级和接受风险：具名评审裁决或会议记录。

外部资料可以说明背景或规模，不能单独证明某个具体客户会购买或改变行为。客户口头表达可以证明其观点，不能自动证明市场普遍性或技术可行性。

## 三、最小记录字段

关键主张至少记录：

- 主张编号与内容
- 状态
- 主张类型
- 来源及精确定位
- 口径、单位、基线、时间窗和适用范围（数字适用）
- 反证或冲突
- 负责人和最迟验证时间（未验证适用）
- 影响的 PR、FAQ、PRD 条目

“没有来源”不是错误，但必须降级为假设或未知；错误是把它继续写成事实或承诺。

### 编号规则与行内引用

默认编号类别如下；项目已有体系时可以沿用，但不得混用两套体系：

- `C-01`：主张（Claim），包括需要追溯的事实、估算、目标或已批准决定；具体状态另列，不靠编号判断。
- `H-01`：假设（Hypothesis），指尚待验证且可判真假的关键命题。
- `X-01`：冲突（Conflict），指来源、口径或结论之间尚未解决的冲突。
- `D-01`：裁决（Decision），指有权人对范围、优先级或风险取舍作出的决定。
- `R-01`：PRD 范围或需求条目（Requirement），用于交付阶段回指。

编号按类别递增，在被其他文档引用后保持稳定，不因排序或删项而整体重排。

**短题名登记。** 台账为每个编号登记唯一短题名（≤10 字），作为全项目权威源；所有文档复用同一短题名，变体视为一致性检查未通过。PRD 范围条目（R）以 PRD 条目标题为短题名，不在台账登记。

**行内引用，按文档分层：**

- PR 正文零编号，“PR 承诺 ↔ 支撑”的追溯在台账与 FAQ 中完成。
- FAQ 引用用“短题名（编号）”；同条目重复出现后可只用短题名。
- PRD 条目标题自带编号（如 `R-01 静音检测`），正文交叉引用用“短题名（编号）”；表格中编号与标题已同列并排时，格内可单用编号。
- 单句引用超过 3 个编号时改列表，每项一条“短题名（编号）”。

任何交付给人的文档只要出现这些代码，就必须在目录后或首次出现前增加“编号说明”，列出本文件实际使用的类别及中文含义。例如：`C = 主张，H = 待验证假设；编号用于跨 PR、FAQ、PRD 和台账追溯。` 不得只给代码而让读者猜测分类。

## 四、冲突处理

1. 不用投票、职位或文风自行消解事实冲突。
2. 并列写出来源 A、来源 B、冲突点、对产品的影响和可验证方式。
3. 事实冲突通过补证据解决；范围与风险偏好冲突由有权人裁决。
4. 裁决改变产品口径时，同步回写台账、PR、FAQ 与 PRD。

## 五、数字检查

任何精确数字至少回答：谁的数字、测的是什么、怎么测、基线是什么、目标时间是什么、样本多大、适用于哪里。答不全时：

- 能给计算依据：写区间，标“有据估算”。
- 只能表达期待：标“未来目标”。
- 尚无依据：写“未知待补”，不得从历史范例复制阈值。

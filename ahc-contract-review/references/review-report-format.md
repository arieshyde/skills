# 审核意见输出格式（摘抄式）

撰写审核意见 MD 前读取本文件。

## 去重与分级规则

各层审查（文字/结构/实质风险）与数字核验发现的问题，先汇总去重再分级：

- 同一问题只列一条，按 ❗ 必改错误 > 🔴 重大风险 > 🟡 一般风险 > 🟢 提示事项 归入最高一级，只给一套修改建议与示例。例如金额计算错误既是必改错误又构成付款风险，只列入 ❗ 必改错误，风险后果写进该条的"修改原因"。
- 低级别审查中的补充信息并入该条"修改原因"，不另立条目；审核汇总索引中每个问题也只出现一次。
- 不同问题即使位于同一条款，仍分别列出。

## 报告结构

1. **审核汇总**：全部问题的一句话索引
2. **整体签约建议**：建议签 / 修改后签 / 不建议签 + 理由（底线条款与谈判筹码的区分见 SKILL 第八节）
3. **头部**：合同名称、甲方、乙方、标的物/交易内容、合同金额（含核验结论）、审核立场（我方身份）、审核日期
4. **数字与算术核验记录**：核算内容和结果列举出来
5. **分级意见**，按 ❗ 必改错误 🔴 重大风险 🟡 一般风险 🟢 提示事项 排列：
   - ❗ 必改错误：排在最前，即 SKILL 第 1 层审查与数字核验中判定为错误的问题
   - 🔴 重大风险：不修改不宜签约
   - 🟡 一般风险：建议修改，可作谈判筹码
   - 🟢 提示事项：可优化，不影响签约大局
6. **每条意见四要素**：
   - 位置与摘要：第 X 条 / 章节号 + 一句话摘要
   - 原文摘抄：引用块完整摘录待修改原文（必须与原文逐字一致）
   - 修改示例：建议条款全文，改动处加粗标注
   - 修改原因：风险分析与法律依据

## 格式规范

- 正文用列表和键值对，不用箭头符号（→、←）描述顺序，改用编号列表或文字叙述
- 全程中文，不夹杂英文
- 表格仅用于数据对比类内容（如汇总索引），列表能表达的不用表格
- 文件中不写文件路径、不出现真实姓名（当事人用"甲方""乙方"或公司简称）
